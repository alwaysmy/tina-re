# sparse_dll.dll 算法逆向（自研实现的工程参照）

> 2026-10-19。目标：把 TINA 稀疏求解器的数据结构、排序、分解、求解语义完整记录下来，
> 供我们自己的 MNA 实现对照，避免 pivoting/ordering/容差/奇异矩阵这些工程坑。
> 证据：`out/sparse_exports.txt`、`out/round27_sparse.txt`、`out/round28_sparse.txt`、
> `out/round30_sparse.txt`、`out/round31_sparse.txt`。

## 1. 结论

- 本质是 **left-looking 稀疏 LU**（SuperLU 风格），**分解阶段不做数值选主元**，
  直接用对角元；零对角 → 返回状态 102（奇异）。
- 选主元/降填充在 **reorder 阶段**完成（Markowitz 风格，带阈值）。
- 对角元存成**倒数**（`1/d`），L/U 的缩放与教科书 LU 不同，但解相同。
- 默认 pivot/drop 容差 = **1e-3**（double，矩阵对象 +0x88）。
- 所以“换个 LU 库”在数学上等价，但要复现 TINA 的行为，需要：
  **排序 + 不选主元 + 1e-3 阈值 + 倒数对角**。

## 2. 数据结构

### 2.1 矩阵对象（0xE8 字节）

| 偏移 | 含义 |
|---|---|
| +0x00 | 预留/状态 |
| +0x10 | 模式：0=求解模式，1=LU 模式（`cLUfac` 置 1） |
| +0x14 | 内部编号计数器（下一个可用行号） |
| +0x18 | 行指针数组（行头 = 对角元素；`row[i]+0x18` 为行内下一元素） |
| +0x28 | 状态码（0..100 正常；>100 错误；102=奇异） |
| +0x2C | 已使用的最大外部行/列号 |
| +0x30 / +0x34 | 内部→外部 / 外部→内部 编号映射 |
| +0x38 | “已分解”标志（luFac 前置要求为 0，完成后置 1） |
| +0x40 | 列链表数组（每列一个元素链） |
| +0x48 | 魔数 `0x772773` |
| +0x4C | 工作/解向量缓冲（double*） |
| +0x54 | 输出置换数组（解向量回排用） |
| +0x58 | 输入置换数组（RHS 取数用） |
| +0x6C | 脏标志（元素/数值变动置 1；solve 前置要求为 0） |
| +0x88 | pivot/drop 阈值（double，默认 **1e-3**） |
| +0x8C | 阈值高 32 位（与 +0x88 组成 double） |
| +0x94 | 复数/实数变体标志 |
| +0x9C / +0x98 | 排序阶段的临时计数 |
| +0xA4 | 矩阵阶数 n（外部最大编号） |
| +0xA8 | 索引 0 的哑元元素（`makeElt(0,*)` 返回它） |

### 2.2 元素对象（约 0x20 字节）

| 偏移 | 含义 |
|---|---|
| +0x00 | double 数值 |
| +0x10 | 行号（外部编号；排序后可能变化） |
| +0x14 | 列号（外部编号） |
| +0x18 | 行内下一元素指针 |
| +0x1C | 列内下一元素指针 |

### 2.3 编号与插入

- `makeElt(i,j)` 先把外部编号通过 `+0x34` 映射成内部编号（`FUN_00402f18`）；
  首次出现的行/列会增长数组并分配编号（最少 6×6，见 `newMatrix`）。
- 同一 (i,j) 重复插入返回**同一元素指针**（不会叠加值）。
- `i==0` 或 `j==0` 返回 `matrix+0xA8` 哑元。
- 值由调用方写入元素 `+0`（`_SMPmakeElt` 本身不接收数值参数）。

## 3. API 语义（按调用顺序）

| 调用 | 语义 / 前置条件 |
|---|---|
| `newMatrix(&mat)` | 分配 0xE8 对象；维度从 0 开始、内部最少 6；写魔数；阈值 1e-3；返回状态（0=成功） |
| `makeElt(mat,i,j)` | 建模式/取元素指针；重复返回同一指针；不设值 |
| `clear(mat,cb)` | **把所有元素值清零**、重置统计；应在写值**之前**调用 |
| 写值 | `element+0x00 = double` |
| `preOrder(mat)` | 符号排序（近似最小度：反复取度数最小的节点消去，`FUN_00401448`） |
| `reorder(mat, ...)` | 数值排序（Markowitz 风格，阈值来自 +0x88，默认 1e-3；`FUN_0040340c`） |
| `cLUfac(mat)` / `luFac(...)` | 前置：+0x38==0；left-looking 列分解；对角主元，零 → 状态 102；完成后 +0x38=1，对角存 `1/d` |
| `solve(mat,b,x,cb)` | 前置：+0x38!=0 且 +0x6C==0；按 +0x58 取 RHS，前代/回代，按 +0x54 写回 `x`（**第 3 参**） |
| `cSolve(mat,b,p3,x,p5)` | 同上，但**解向量是第 4 参**（第 3 参是别的指针；传 0 会写空指针 → 崩溃） |
| `destroy(mat)` | 释放全部数组 |

## 4. 数值细节（复现要点）

1. **不选主元**：分解时直接取对角元 `A[k,k]`；`A[k,k] == 0.0` → 状态 `0x66`（102），
   不会自动换行/换列。排序阶段负责把非零元换到对角（Markowitz）。
2. **对角缩放**：分解后对角存 `1.0 / d`，不是 `d`。前代/回代使用倒数，因此
   L/U 的数值与标准 LU 不同；若要逐位对比，必须照此实现。
3. **容差**：默认 1e-3（+0x88）。排序阶段的阈值会被夹在 [0,1]（常量 0.0/1.0）。
4. **置换顺序**：RHS 按 `+0x58` 取数，解按 `+0x54` 回排；两个数组不可混用。
5. **状态码**：0=成功；8=分配失败；102=零主元/奇异；大于 100 都是错误。
   调用方应检查状态，而不是依赖异常。
6. **顺序耦合**：`clear` 在写值后会清零；`luFac` 前置要求未分解；`solve` 前置要求已分解
   且没有新元素（+0x6C）。这是我们之前调用失败的两个直接原因。

## 5. 对我们自研实现的建议

**原则：全面超越 TINA，不强行兼容它的缺陷。** 下列 TINA 行为仅作为参考；
除非为了定位差异，不复制它的不选主元/状态码/倒数对角等实现细节。

| TINA 行为 | 我们的策略 |
|---|---|
| 排序尽在 reorder（Markowitz + 1e-3） | 用 COLAMD/AMD 做填充排序；对角为 0 时**回退到部分选主元**（SuperLU 默认），比 TINA 更稳 |
| 分解不选主元 | `scipy.sparse.linalg.splu(..., diag_pivot_thresh=0.0)` 可近似；默认 `1.0` 是部分选主元，数值更稳 |
| 对角存倒数 | 仅在意逐位对比时复现；一般实现用标准 L/U 即可 |
| 奇异返回 102 | 捕获 `RuntimeError` 并映射为“矩阵奇异/检查接地”错误 |
| 元素重复插入不叠加 | 我们的装配器要么去重，要么显式允许重复并累加（更常见） |

**建议默认**：采用 **COLAMD + 部分选主元（SuperLU 默认）**，并在诊断信息里记录
“TINA 在此处不选主元”这一点；只有在需要与 TINA 数值逐位对齐时，才切到
`diag_pivot_thresh=0` + 排序复现。

## 6. 对拍方法

- 小矩阵：手工构造 3×3/4×4，比较解与残差；
- 奇异矩阵：零对角/全零行，确认我们的实现给出明确错误（而不是 NaN）；
- 大矩阵：用 TINA 导出的 MNA 矩阵（后续可从引擎调用点 dump）做基准；
- 任何差异先看：排序、是否选主元、对角缩放、置换方向。
