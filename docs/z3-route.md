# Z3/SAT 路线说明（G 构造求解备份计划）

> 背景：BATTLELOG 三十二轮提出「Z3/SAT 解 P0」路线；本文件把它写清楚，并并入 round10-14 的新事实。

## 1. 路线是什么

把 G 的**未知部分**编码为位向量变量，把 oracle 实测点编码为约束，交给 SMT/SAT 求解器求出未知量。

原设想（三十二轮）：
```
G(x) = extract( compress(P0, pad(x)) )       # 假设模型族
未知: P0 ∈ 2^256（256bit 链初值）
约束: G(0⁸)=7455d14e72cf5821, G(ff⁸)=…, … 共 5 点 = 320bit
      → 超定（320 > 256），若模型族正确，求解器可唯一解出 P0 → 直接得到 G → CLI
```
“树是纯位运算+加法+循环移位”（加、异或、与、或、ROTL）→ 全部可由 z3 BitVec 运算直接编码；
求解器（位爆破 + CDCL）在这类 ARX 结构上通常可行，只是可能耗时（小时级）。

## 2. round10-14 之后，这个路线的具体抓手变了（都是好消息）

1. **压缩函数 = 标准 RIPEMD-256**（已用二进制 p-code 模拟 + 官方向量双重确认）。
   → Z3 编码不用再依赖手抄转录：直接编标准 RMD256（f/K/r/s 表全公开，本仓库已归档 Python 版）。
2. **未知初值的来源更明确了**：如果 G 用哈希链，真正未知的是
   `S0`（8×32bit 链状态初值，可能不是标准 IV——取决于「解密前哈希对象被喂入过什么」）。
   `S_{n+1} = Finalize(Update(S_n))`（自哈希回灌链，见 findings §11.2）——S0 一解出，整条链唯一决定。
3. **约束数可以远多于 5 点**：oracle 可用 `oracle_tail.py` 继续造点（~90s/个）；
   甚至 `ks_ground.bin` 的 1452 对 (x, G) 本身就是约束源（每对 64bit）。
   → 几百比特的未知 vs 数万比特的约束 = 极度过定 → 一旦模型族正确，求解近似"直接读出"。
4. **模型族的候选收窄**（本轮已排掉：标准 Blowfish 全部候选、纯 RMD256 单哈希切片、纯链首三态）。

## 3. 执行的正确顺序（先便宜后昂贵）

1. **全管线模拟器参数搜索**（首选，最便宜）：
   用本仓库已有素材（Blowfish + RMD256 + 两个引擎 + 委托链语义）遍历
   {密钥来源 × 链初值 × 模式/门控}，直接对 `ks_ground.bin` 逐块比对。
   若命中 → 不需要 Z3，直接产出。
2. **小规模 Z3（单压缩）**：若结构确认但个别常量未知，把单个 RMD256 压缩编成 z3 约束求解。
3. **大规模 Z3（链 + 引擎联合）**：把「链迭代 + 模式引擎 + Blowfish 装订」整段编码。
   规模：一次 128 步 ARX × N 块；建议限 2-3 块、逐步放开。

## 4. 工具

- `pip install z3-solver`（未安装则装）
- 编码骨架（可直接用）：`scripts/test_g_rmd256.py` 里的 `compress()`——替换算术为 `z3.BitVec` 运算即是 Z3 版本；
  从「具体值」到「符号值」只需换类型（ROTL/加法在 z3 中同名支持）。
- 造新 oracle 点：SpiceHappy `re/oracle_tail.py`（需 TINA 运行时环境）

## 5. 判定标准（避免自欺）

- 解出的参数必须在**未参与求解**的新 oracle 点上全部复现（留出验证集）；
- 与 `ks_ground.bin` 的少量抽样块对拍通过后，再全量跑 388 库；
- 任何一步失败都视为模型族错误，回到第 1 步更换结构假设。
